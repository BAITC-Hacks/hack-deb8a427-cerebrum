# Архитектура интеграции

Актуальный вход и команды заданы в [README](../README.md) и
[PARTICIPANT_GUIDE.md](../PARTICIPANT_GUIDE.md). Ранее в репозитории
использовалась синтетическая среда команды; её старые схемы и метрики не
описывают официальный evaluator.

## Источники и граница изменений

Официальные `environment.py`, `mock_environment.py`, `scoring_core.py`,
`agent_template.py`, `local_eval.py` и `make_submission.py` копируются
из пакета участника без правок. Входные CSV корня и `data/` восстанавливаются
локально командой импорта из README и исключены из Git. Список и хеши
файлов источника — в `scripts/participant_package_manifest.json`.

Код агента — `agent.py`, `candidates.py` и `llm_advisor.py`. Прежний симулятор и генератор
демонстрационных данных служат только поддержкой тестов в `tests/support/`.
Ни один синтетический генератор команды не готовит вход для официального
evaluator или экспортёра.

## Поток выполнения

`python run.py` подготавливает `.venv`, проверяет/импортирует пакет и запускает
`preview_server.py` с интерфейсом `web/index.html`. `jury_eval.py` проверяет
решения через публичный API и получает итог официального evaluator. Запуски
изолированы в дочерних процессах с таймаутом 600 секунд. Git и Node.js для
демонстрации не нужны. `--check` сохраняет проверку seed 42 и 0–9, воспроизводит
экспорт дважды и возвращает ненулевой код при неуспехе.

1. Официальный `local_eval.py` создаёт среду с предоставленной аудиторией,
   тарифами и каналами и вызывает `Agent.act(env)`.
2. Агент строит варианты аудитории, целевого тарифа и канала по публичным
   полям `env`. Предоставленная история другой выборки может служить
   предварительной оценкой, но не подменяет пилот на целевой аудитории.
   При `CEREBRUM_LLM=1` модель может переставить первые 20 гипотез по агрегатам.
   Её ответ проверяется как перестановка; ошибки возвращают исходный порядок.
3. Агент проводит пилоты через `env.run_pilot()`, обновляет оценки по их
   результатам и отслеживает общий остаток бюджета, контактов и пилотов.
4. Агент возвращает от 1 до 10 кампаний с допустимыми фильтрами. Официальный
   evaluator проверяет ограничения и считает результат на мок-эффектах.
5. Официальный `make_submission.py` повторно запускает агента и создаёт
   `submission.csv` для проверки и сдачи; проверенный файл включается в Git.

## Кандидаты и неопределённость

Базовые когорты строятся по текущему тарифу и ARPU-сегменту. Если когорта
превышает лимит 5 000 абонентов, она уточняется публичными сегментами
потребления данных и звонков. История смен тарифов ранжирует варианты
для пилота: ARPU до смены помогает оценить сегмент исторической выборки.
Это предварительная гипотеза, а не наблюдение эффекта в целевой аудитории.

Относительная неопределённость prior со значением 1.0 — эвристический
параметр агента. Его нельзя описывать как выборочное стандартное отклонение
или поле публичного результата пилота. Положительный, но шумный результат
первого пилота агент подтверждает дополнительным наблюдением до выбора
платного канала. Финальное решение использует реальные результаты пилотов
и остатки ресурсов.

Публичный `conversion_multiplier` помогает оценить приоритет эксперимента с
другим каналом. Он не заменяет собственный пилот этого канала. Все успешные
пилоты записываются в `Agent.trace`: этап, размер, средняя оценка, стандартная
ошибка и нижняя оценка после цены контакта. В трассировке нет ID абонентов.

Для каждого абонента учитывается лучший полученный эффект, а контакты
расходуют ресурс и стоимость независимо от повторов. Эффект выражен
процентом от ARPU конкретного абонента; исторические изменения ARPU не
следует трактовать как готовый эффект перехода на целевой аудитории.

## Безопасность и проверка

Агент не читает скрытые эффекты, приватные поля среды и файлы оценки.
Предоставленные CSV истории можно использовать только как открытые данные
пакета. Официальные скрипты и входные CSV не редактируются для улучшения
оценки. Проверочные команды и границы результата перечислены в
[плане тестирования](test-plan.md) и [SECURITY.md](../SECURITY.md).
