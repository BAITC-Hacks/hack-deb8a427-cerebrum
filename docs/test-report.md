## submission.csv

Файл создан экспортёром и содержит заголовок и 3 строки кампаний.
Две генерации дали одинаковый SHA-256:

`dd0dcffb1c9e937c9e5377003a4c975960bf7e4c9640936ad91a0f96d83e17eb`

Это демонстрационный CSV. Совместимость с официальной сдачей не проверена.
Содержимое совпало с версией main после нормализации переводов строк.
Git на Windows может хранить CRLF в рабочей копии, экспортёр пишет LF;
проверять воспроизводимость следует между двумя генерациями.

## Найденные проблемы и решения

1. В глобальном Python не было NumPy. Решено установкой requirements в новый venv; глобальные пакеты не использованы.
2. При bootstrap preflight дал `git-file-list-unavailable`: Git отвергал каталог с другим владельцем. README содержит настройку safe.directory только для текущей папки и текущей сессии; путь передаётся с прямыми слэшами. После неё все проверки прошли. Глобальная конфигурация Git не изменена.
3. Первоначальное сравнение CSV с байтами checkout выявило LF/CRLF. Две генерации побайтно совпадают; нормализованный Git diff не содержит изменений CSV. Это не ошибка алгоритма.
4. В чистом прогоне окончательного README ошибок не было. Файлы агента, evaluator, экспортёра, требований и генератора не изменены; комментарий о кодовой ошибке капитану не требовался.
