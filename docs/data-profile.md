# Профиль данных участников HackAlem AI

**Статус: исходные CSV и словари участников не предоставлены. Фактический
профиль данных пока не построен.**

Ветка `qa/data-profile` создана от `origin/main` (`3a048e4`). В этой версии
репозитория есть только README команды. В другой ветке команды
`feat/pilot-campaign-agent` имеется демонстрационный `submission.csv`, но это
экспорт плана кампаний, не исходный датасет участников. Он не использован.
Приложенные ранее документы описывают данные и правила кейса, но не содержат
самих CSV. Числа из описания кейса не подставляются вместо измерений.

Данные кейса синтетические. Этот анализ не позволяет делать выводы о реальном
бизнесе Beeline.

## Что сейчас установлено

| Запрошенная проверка | Результат |
| --- | --- |
| Число строк, колонок, типы, пропуски, полные дубли и диапазоны | Не вычислены: нет CSV |
| Уникальные абоненты в customer_profile | Не вычислены: нет таблицы и подтверждённого имени ключа |
| Распределения arpu_segment, data_segment, call_segment и текущего тарифа | Не вычислены |
| Диапазон predicted_arpu | Не вычислен |
| Пустые и неизвестные тарифы, соответствие словарю | Не проверены: нет профиля и словаря |
| Согласованность идентификаторов между файлами | Не проверена: нет файлов и описания связей |
| Сегменты вне документации | Не проверены: нет словаря допустимых значений |

Отсутствие измерений не означает нулевые пропуски или успешную проверку.
Скрипт не читает evaluator, генераторы данных, состояние среды или секреты.

## Воспроизведение

`analysis/profile_data.py` использует только стандартную библиотеку Python
3.10+. Установка зависимостей и изменение `requirements.txt` не нужны.

Фактически выполненная команда из корня репозитория:

```powershell
python -X utf8 analysis/profile_data.py --data-dir .
```

Результат: **код 2**, CSV не найдены; все зависящие от них проверки отмечены
`NOT_CHECKED`. Это ожидаемый результат при отсутствии входных данных, а не
успешный профиль. Для этого запуска `.` — проверенная папка без CSV.

После получения пакета нужно указать папку, содержащую **только выданные
участникам CSV и словари**, без submission, демонстрационных и посторонних
таблиц. Скрипт рекурсивно читает её файлы с расширением `.csv`. Папка может
находиться вне репозитория: копировать исходные данные сюда не требуется.

```powershell
python -X utf8 analysis/profile_data.py --help
python -X utf8 analysis/profile_data.py --data-dir 'ПУТЬ_К_ПАКЕТУ'
```

Вторая команда — шаблон будущего запуска, а не уже выполненная проверка.
Без явных сопоставлений она выдаст общий профиль доступных CSV, но оставит
неопределённые проверки как `NOT_CHECKED`. Имена ключей не угадываются по
демонстрационной среде. После изучения реальных заголовков и словарей задаются:

| Аргумент | Значение |
| --- | --- |
| `--customer-profile` | Относительный путь к профилю, по умолчанию `customer_profile.csv` |
| `--customer-id` | Точное имя столбца идентификатора абонента в профиле |
| `--current-tariff` | Точное имя столбца текущего тарифа в профиле |
| `--tariff-key` | `относительный/словарь.csv:СТОЛБЕЦ_ТАРИФА` |
| `--id-column` | `относительный/файл.csv:СТОЛБЕЦ_ID`; повторить для сопоставляемых файлов |
| `--segment-rule` | `arpu_segment=словарь.csv:СТОЛБЕЦ_ЗНАЧЕНИЙ`; аналогично для двух остальных сегментов |
| `--encoding` | По умолчанию `utf-8-sig`, поддерживает UTF-8 с BOM и без BOM |
| `--delimiter` | По умолчанию запятая; для другого CSV-разделителя указать явно |
| `--output` | Необязательный путь к Markdown-отчёту; без него отчёт выводится в stdout |

Сопоставления являются параметрами профилирования, а не утверждением о схеме
ещё не полученных данных. `--segment-rule` поддерживает словарь, в котором
допустимые значения перечислены отдельными строками в указанном столбце.
Если настоящий словарь описывает сегменты свободным текстом или хранит их
иначе, потребуется адаптация чтения по фактическому формату. Нельзя подменять
документированный список категориями из самого customer_profile.

Для сохранения окончательного отчёта после настройки сопоставлений можно
добавить `--output docs/data-profile.md`: это **перезапишет этот документ**.
Перед сохранением следует проверить агрегированный отчёт в stdout и записать
полную команду с фактическими сопоставлениями в описание PR.

Коды завершения:

- `0`: запрошенные проверки выполнены, отмеченных проблем нет;
- `1`: профиль построен, найдены проблемы (`ISSUE`);
- `2`: входные данные, сопоставления или чтение неполны (`NOT_CHECKED`/`ERROR`).

При одновременном наличии проблем и невыполненных проверок возвращается 2;
все статусы остаются в отчёте. Сравнение множеств ID выводится как `INFO`:
различные выборки не обязаны совпадать, и без смысла связи объявлять различие
ошибкой нельзя.

## Методика и ограничения

- Файлы обрабатываются в стабильном порядке. Отчёт включает относительные
  пути и SHA-256 исходных файлов, не содержит времени запуска. При одинаковых
  входах, параметрах и версии скрипта результат воспроизводим.
- CSV не имеет встроенных типов: скрипт сохраняет строки и выводит тип по всем
  непустым значениям. Для чисел используется `Decimal`, без потери точности
  из-за двоичного float. Даты остаются строками, если не подтверждена схема.
- Пропуск — пустая строка либо только пробельные символы. `NA`, `null` и другие
  текстовые маркеры автоматически не заменяются: их смысл нужно установить
  по словарю. Неконечные числа исключены из min/max; для predicted_arpu они
  отмечаются как проблема наряду с нечисловыми значениями.
- Полный дубль — повтор всей строки по прочитанным строковым значениям;
  считается число повторов сверх первого вхождения. Пробелы и ведущие нули
  сохраняются, поэтому разные строковые ключи не склеиваются.
- Указываются min/max конечных чисел. В смешанных колонках это диапазон
  числовой части, рядом указано число распознанных числовых значений. Для
  явно сопоставленных ключей и очевидных колонок ID/телефона диапазоны скрыты.
- Профиль выводит агрегаты, распределения сегментов и тарифов; значения ID
  абонентов и строки источников не экспортируются. Исходники не изменяются.
- Для точного подсчёта дублей данные держатся в памяти; расход памяти растёт
  с размером пакета. Потоковая обработка очень больших выгрузок не реализована.
- Идентификаторы сравниваются попарно только для явно перечисленных файлов
  и колонок одной сущности. Скрипт не выводит неизвестные ID, только их число.
  Он не утверждает корректность смысловых связей и периодов без словаря.

## Что полезно для алгоритма

Пока нет оснований выбирать тариф, канал или сегмент по этому отчёту.
После получения CSV нужно проверить следующие свойства до использования данных:

1. Повторные ключи при объединении таблиц могут увеличивать размер аудитории.
   Нужно отличать дубли строк от допустимых нескольких периодов одного абонента.
2. Маргинальные распределения категорий помогают оценить покрытие, но лимит
   кампании проверяется на пересечении всех её фильтров.
3. Пустые или отсутствующие в словаре тарифы требуют явной обработки до
   построения допустимых кампаний.
4. Диапазон predicted_arpu помогает выявить пропуски и некорректные значения,
   но не оценивает эффект перехода. Эффекты по-прежнему исследуются пилотами.

Алгоритм выбора кампаний в этой ветке не изменялся.

## Проверка самого скрипта

Выполнены 25 проверок на маленьких временных тестовых таблицах, созданных
в `TemporaryDirectory` вне репозитория. Проверены числовые диапазоны, пропуски,
точные дубли, неизвестные тарифы и сегменты, ведущие нули в ID, пересечения
ключей, неконечные числа, отсутствие входов и сопоставлений, ошибки кодировки,
повторные заголовки, некорректная ширина CSV, сохранение Markdown и коды
завершения. Повторный отчёт совпал, байты входных CSV не изменились.
Тестовые таблицы не являются данными участников и не используются для выводов.

Фактический профиль, сверка со словарями и проверка на пакете организаторов
остаются невыполненными до получения исходных данных.

## Внешний тестовый набор IBM

По отдельному запросу найден открытый
[IBM Telco Customer Churn](https://github.com/IBM/telco-customer-churn-on-icp4d/blob/d5371f5d83a446ad5673cbcca3b814b926491f8a/data/Telco-Customer-Churn.csv).
Использованы первые 500 строк данных в исходном порядке, без изменения колонок
и значений. Это небольшой тест чтения и профилирования CSV, не пакет HackAlem
и не репрезентативная выборка для оценки алгоритма кампаний.

Исходный файл: 7 043 строки, 21 колонка; зафиксирован коммит IBM
`d5371f5d83a446ad5673cbcca3b814b926491f8a`.
SHA-256 исходника:
`16320c9c1ec72448db59aa0a26a0b95401046bef5d02fd3aeb906448e3055e91`.
Тестовый CSV сохранён с заголовком в UTF-8 без BOM, переводы строк LF,
размер 68 160 байт. Его SHA-256:
`774cf85c875e87abdce60c6f2e8f574f415e5e8aa3f1588c3f53a6e21ca722b8`.

Для воспроизведения выборки: скачать CSV по ссылке Raw из указанного коммита,
проверить SHA-256, прочитать стандартным `csv.reader` с `utf-8-sig`, записать
первые 501 записи (заголовок и 500 строк) через `csv.writer` с UTF-8 и
`lineterminator="\n"`. Исходный файл целиком в репозиторий не сохраняется.

Локальная команда проверки (из корня репозитория, PowerShell):

```powershell
$sampleDir = Join-Path $env:TEMP 'cerebrum-telco-qa-iglvw15e'
python -X utf8 analysis/profile_data.py --data-dir "$sampleDir" --customer-profile Telco-Customer-Churn-500.csv --customer-id customerID --output "$sampleDir/profile.md"
```

Папка временная и может быть очищена системой; для повторного скачивания
допустима другая папка с заменой значения `$sampleDir`. Внутри находятся CSV,
метаданные источника и локальный отчёт. Они не добавлены в Git.

| Измерение | Фактический результат |
| --- | --- |
| Строк / колонок | 500 / 21 |
| Уникальных customerID | 500 |
| Пустых / повторных customerID | 0 / 0 |
| Полных дублей | 0 |
| Пропусков | 1 в TotalCharges; в остальных колонках 0 |
| tenure, min/max | 0 / 72 |
| MonthlyCharges, min/max | 18.95 / 116.05 |
| TotalCharges, min/max по 499 непустым значениям | 19.15 / 8468.2 |
| Повторное формирование отчёта | Совпадающий вывод |
| Сохранность входного CSV | SHA-256 до и после совпадает |
| Ключи абонентов в выводе | Значения customerID не выведены |
| Код завершения | 2, ожидаемые NOT_CHECKED для отсутствующих полей кейса |

Число строк, колонок, ID, дублей и пропусков дополнительно пересчитано отдельным
проходом через `csv.DictReader`; диапазоны — через `Decimal`.
Отчёт содержит полный список колонок и их профили.

В наборе нет `arpu_segment`, `data_segment`, `call_segment`, `predicted_arpu`,
словаря тарифов и связанных таблиц HackAlem. Поля `Contract` и `MonthlyCharges`
не подменяют текущий тариф и predicted_arpu. Проверки этих сущностей остаются
`NOT_CHECKED`; запуск агента и выводы об эффектах кампаний на этом наборе
не выполнялись. Этап профилирования официальных данных остаётся незавершённым.
