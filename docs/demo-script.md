# Сценарий демонстрации Cerebrum

Показываем локальную синтетическую версию команды. В начале и в конце назвать
ограничение: это не данные реального оператора и не официальный evaluator
организаторов. Не переносить результат на Beeline или будущий судейский балл.

## 1. Проблема и пользователь

«Маркетинговый аналитик выбирает, кому предложить смену тарифа и через какой
канал. Кампания вслепую может вызвать downsell: абонент платит меньше,
а компания дополнительно оплачивает коммуникацию».

## 2. Решение

«Agent.act(env) исследует аудиторию небольшими пилотами, учитывает наблюдённый
эффект и неопределённость, затем формирует до 10 кампаний. Пилоты и финальный
план расходуют общий бюджет и общий лимит контактов».

## 3. Подготовка

До выступления выполнить установку README и открыть PowerShell в корне
репозитория с активированной `.venv`. Проверить preflight по README.
Секреты и `.env` не показывать. CSV аудитории не выводить на экран целиком.

## 4. Показ входа


Ожидается 23441×6 в профиле и 21×4 в тарифном словаре. Объяснить, что это
фиксированный синтетический генератор seed 2026. Диапазоны, пропуски и
распределения уже приведены в [data-profile.md](data-profile.md). Эффект
перехода нельзя узнать из этих таблиц без пилота.

## 5. Основной запуск

```powershell
python local_eval.py
```

Показать строку `UNOFFICIAL`, код завершения и строку `OK`. В проверенном
прогоне seed 42 получены 3 кампании, 20 пилотов, 10775 контактов и расходы
97842. Эти цифры — пример из [отчёта](test-report.md); на сцене озвучить
фактический вывод. `net_gain` относится только к этой mock-среде.

## 6. Пилоты, кампании и ресурсы

Для структурированного показа повторить тот же детерминированный сценарий:

```powershell
$evaluation = python local_eval.py --json | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'Evaluation failed; inspect the reported error.' }
$run = $evaluation.reports[0]
if (-not $run.ok) { throw 'The plan was not accepted.' }
$run.pilot_history | Select-Object pilot_id,target_tariff,channel,n_customers,mean_arpu_uplift,net_gain | Format-Table
$run.campaigns | Format-List
$run.metrics | Format-List
```

Показать:

- размеры пилотов и измеренный эффект;
- выбранные тарифы, каналы и фильтры финального плана;
- `campaign_sizes`, `pilots_count`, `contacts_used`, `communication_cost`;
- `remaining_contacts`, `remaining_budget` и `net_gain`.

Отдельно отметить: финальный охват ограничен 5000 на кампанию, расходы
включают пилоты, повторные контакты также расходуют ресурсы. Отрицательный
результат не скрывается; допустимый план не гарантирует прибыль.

## 7. Экспорт

```powershell
python make_submission.py
Get-Content submission.csv
Get-FileHash submission.csv -Algorithm SHA256
```

Показать заголовок и строки кампаний. Файл не содержит ID абонентов или
секретов. Это демонстрационный экспорт команды; официальный формат сдачи
ещё требует сверки. Для доказательства повторяемости можно повторить экспорт
и сравнить хэш, как описано в README.

## 8. Архитектура и отличие подхода

«Генератор создаёт профиль и справочник. LocalEnvironment предоставляет
публичные таблицы и пилоты. Агент строит непересекающиеся аудитории,
исследует тарифы, повторяет неоднозначные пилоты и пробует другие каналы.
Evaluator проверяет план, экспортёр сохраняет CSV».

Уточнить, что именно реализовано:

- Размер повторного пилота зависит от наблюдённой ошибки и предполагаемого
  эффекта, с ограничением 10–200 и резервированием ресурсов.
- Среднее и стандартная ошибка объединяются по пилотам. Оценка неопределённости
  эвристическая, не доказанная доверительная гарантия после адаптивного выбора.
- Каналы сравниваются по наблюдениям с учётом стоимости и размера аудитории;
  агент не предполагает заранее, что дорогой канал обязательно выгоднее.
- Внешнего API нет: основной локальный алгоритм работает без ключа.
  Сетевой fallback не заявляется как реализованная интеграция.

## 9. Честные ограничения

Нет официального пакета/подтверждения формата сдачи. Разведка может пропустить
лучший вариант, перенос оценки на суженную аудиторию может смещать результат.
При отсутствии успешного пилота или допустимой группы агент выдаёт ошибку.
В adverse все 10 проверенных запусков убыточны, хотя лимиты соблюдены.
Дедлайн внутри агента не прерывает зависший чужой env; локально процесс
контролируется оболочкой. Веб-интерфейса и развёрнутого сервиса нет.

## Описание для формы сдачи

**Название:** Cerebrum — агент тарифных маркетинговых кампаний.

**Описание:** Агент помогает маркетинговому аналитику сформировать план
тарифных кампаний: исследует сегменты пилотами, оценивает наблюдённый эффект
и выбирает тарифы и каналы с учётом бюджета и контактов. Реализованы локальная
синтетическая среда, проверка ограничений и воспроизводимый экспорт плана;
совместимость с официальным пакетом организаторов пока не подтверждена.

**Технологии:** Python, NumPy, pandas, стандартные unittest и multiprocessing;
без LLM и внешних API в рабочем контуре.

**Основной результат:** `Agent.act(env)` возвращает план из 1–10 кампаний,
основанный на пилотах; в локальной проверке подтверждены лимиты и повторяемость
демонстрационного `submission.csv`. Фактические метрики — в test-report.md.
