# Аудит безопасности и зависимостей

Дата: 23 сентября 2026 года. Ветка: `security/audit`. База: `688581e`
(`origin/main`, после слияния PR №2 и №3). Проверены текущие файлы этого
репозитория, доступная локальная Git-история и фактический `requirements.txt`.
Данные и evaluator организаторов отсутствуют: выводы относятся к локальной
реализации команды, как согласовано для этого этапа.

## Область и результаты

В проверенной области не обнаружено совпадений по используемым сигнатурам
секретов, отслеживаемых `.env`/credentials или явных проблем закрепления
прямых зависимостей. Это ограниченный статический аудит, не доказательство
отсутствия всех секретов или уязвимостей.

Добавлен `scripts/security_audit.py` на стандартной библиотеке Python. Он
использует существующий поиск сигнатур из `scripts/preflight.py`, проверяет
доступные текстовые Git blobs и сообщения commit/tag, правила игнорирования,
пустоту `.env.example`, прямые импорты и установленные версии зависимостей.
Значения секретов, исходные строки и сообщения исключений не печатаются.
Шесть тестов в `tests/test_security_audit.py` проверяют безопасную диагностику,
обнаружение удалённого из текущего дерева секрета, обработку бинарных файлов
и проверку зависимостей. Новые зависимости не добавлены.

Аудит независим от ещё не слитого [PR №4](https://github.com/BAITC-Hacks/hack-deb8a427-cerebrum/pull/4).
Его изменения не копировались в эту ветку. Результаты контрактных тестов ниже
относятся к отдельно проверенному коммиту `c285f84` из `security/robustness`.
Совместная проверка после слияния обоих PR ещё не выполнялась.

## Выполненные команды

Рабочий каталог — корень репозитория. Обычная команда `python` на этой машине
ведёт к заглушке Microsoft Store; использован Python 3.12.14:

```powershell
$securityPython = 'C:/Users/Bekarys/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
Get-Command gitleaks,pip-audit,safety -ErrorAction SilentlyContinue
& $securityPython -X utf8 scripts/security_audit.py
& $securityPython -X utf8 scripts/preflight.py
& $securityPython -X utf8 -m unittest discover -s tests -v
git diff --check
git ls-files -- '*.log' '*.csv' '*requirements*' pyproject.toml setup.py setup.cfg Pipfile poetry.lock
git status --short --branch
```

Внутри audit выполняются только локальные операции:
`git ls-files -z --cached`, `git ls-files -z --others --exclude-standard`,
`git rev-list --objects --all`, `git cat-file --batch-check`, чтение доступных
blob/commit/tag через `git cat-file` и `git check-ignore --no-index`.
Метаданные установленных пакетов читаются через `importlib.metadata`.
Сетевые запросы и установки пакетов скрипт не выполняет.

## Зависимости

| Пакет | Manifest / установлено | Фактическая необходимость |
| --- | --- | --- |
| NumPy | `2.3.5` / `2.3.5` | Используется в `agent.py`, генераторе, среде и тестах для массивов и вычислений |
| pandas | `3.0.1` / `3.0.1` | Используется генератором, средой и тестами для публичных таблиц DataFrame |

Оба пакета декларируют Python `>=3.11`, что соответствует README; проверка
выполнена на Python 3.12.14. Неиспользуемых или неприкреплённых прямых
зависимостей не обнаружено. `requirements.txt` не изменялся.

Транзитивные зависимости и хеши дистрибутивов в manifest не закреплены.
Рекомендация капитану: после согласования целевой среды подготовить lock/constraints
и проверить установку в чистом окружении. Это рекомендация по воспроизводимости,
а не найденная несовместимость. Уязвимости по актуальным базам CVE не оценивались.

## Проблемы, исправления и ограничения

Подтверждённых утечек секретов и дефектов агента в выполненных проверках не
обнаружено. Ротация ключей или переписывание истории не выполнялись. Если
позже найдётся секрет в опубликованной истории, удаления из текущего файла
недостаточно: его нужно считать скомпрометированным и ротировать по процедуре
капитана и организаторов, без публикации полного совпадения.

В этом PR устранён пробел воспроизводимости самого аудита: добавлены команда,
безопасная диагностика и тесты. Production-код, данные, evaluator, зависимости
и существующий preflight не исправлялись и не изменялись.

Оставшиеся риски: сканирование сигнатур не полно; транзитивные пакеты не
зафиксированы; история ограничена доступными refs, недостижимые/удалённые
объекты и игнорируемые локальные файлы не проверяются. Бинарные или non-UTF-8
данные помечаются как непросканированные. Проверка CSV на персональные данные
использует только очевидные заголовки и не является экспертизой обезличивания.
Git author metadata не объявляется утечкой данных абонентов. Исторические
файлы проверяются на сигнатуры секретов, а не на полноту персональных данных.

AST-анализ PR №4 не является sandbox и может пропустить обфускацию. Агент
использовал 20/20 пилотов в 7 из 10 запусков mixed; остальные три — 19/20.
Это допустимо, но оставляет мало запаса. Неблагоприятный сценарий может
оставаться убыточным; повышение mock-score в задачу аудита не входит.

## Безопасность процесса и действия капитана

Сеть хакатона не сканировалась, Wi-Fi не тестировался, внешние системы не
атаковались, ресурсы других команд не проверялись. Работа с GitHub ограничена
обычными операциями Git и созданием PR в официальном репозитории команды.

Капитану необходимо рассмотреть отдельные PR с тестами и аудитом, слить
одобренные изменения самостоятельно и явно подтвердить финальный кандидат
`main`. После этого выполняется этап 4, включая повторную генерацию submission,
проверки после неё и финальный git status. При появлении официального пакета
нужно отдельно сверить контракт env, evaluator, данные и формат сдачи.

Этот отчёт завершает независимый этап аудита, но не является финальным
разрешением на сдачу. Финальный SECURITY GATE пока не выставлялся: этап 4
не запускался без требуемого подтверждения.
