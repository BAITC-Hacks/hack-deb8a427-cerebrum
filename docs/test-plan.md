# План проверки официальной интеграции

Проверяется текущая версия `agent.py` и `candidates.py` с неизменёнными
скриптами пакета участника. Результаты заносятся в
[test-report.md](test-report.md) только после выполнения. Исторические
результаты симулятора команды к этому плану не относятся.

## Подготовка

Из отдельного локального каталога пакета восстановить CSV через
`python scripts/import_participant_package.py --source <путь>`.
Сверить манифест хешей и отсутствие исходных CSV в списке файлов Git.
Установить зависимости из `requirements.txt`.

## Команды

| Проверка | Команда | Критерий |
| --- | --- | --- |
| Окружение | `python -m pip check` | Код 0 |
| Статика | `python scripts/preflight.py` | Код 0; замечания разобраны |
| Тесты | `python -m unittest discover -s tests -v` | Все применимые тесты проходят |
| Официальный smoke | `python local_eval.py` | Seed 42; в тексте нет `FAIL` и отброшенных кампаний, пилоты проведены, лимиты соблюдены |
| Устойчивость | `python local_eval.py --runs 10` | Seed 0–9; в каждом отчёте проверен результат, вариация изучена |
| Экспорт | `python make_submission.py` | Создан непустой `submission.csv`, содержимое проверено и файл добавлен в Git |
| Изменения | `git diff --check` и просмотр `git status` | Нет ошибок форматирования и случайных файлов |

Официальный evaluator перехватывает исключения и может завершиться с кодом 0
даже при `FAIL`; для вывода о прохождении нужно читать текстовый отчёт.
Локальный evaluator использует мок-эффекты, тогда как судейство использует
другие. Поэтому положительный результат и даже десять удачных запусков
не доказывают судейскую эффективность. Проверить, что план действительно
зависит от результатов `env.run_pilot()`, а не только от фиксированных
значений из пакета. Запрещены обращения к скрытым эффектам и правки
официального evaluator ради улучшения результата.

Официальный CLI по guide использует `local_eval.py` и
`local_eval.py --runs 10`; параметры прежнего симулятора `--json`,
`--scenario` и `--data-dir` в этот план не входят.
