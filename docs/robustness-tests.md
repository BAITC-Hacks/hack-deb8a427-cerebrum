# Контракт агента и работа без внешнего API

Добавлены проверки выходного контракта `Agent.act(env)` и работы локального
алгоритма без ключа и сети. Тесты используют `unittest`, существующие
`RewardEnvironment`, `LocalEnvironment` и оболочку `PublicOnlyEnvironment`.
`agent.py`, evaluator, данные и зависимости не изменены.

База проверки: `688581e`, ветка `security/robustness`, 23 сентября 2026 года.
PR №3 с базовым preflight уже находится в этой базе. Среда команды не является
официальным пакетом организаторов; по согласованию проверяется текущий код
репозитория, без утверждения об официальной совместимости.

## Что проверяется

- Наличие и импорт `Agent`, вызов `act(env)`, результат типа `list` из 1–10
  словарей с известными тарифами, каналами и фильтрами.
- Необязательное имя кампании должно быть непустой строкой, если оно задано.
  Неизвестные поля и очевидные дубли запрещены. При сравнении дублей имя
  игнорируется, а порядок значений внутри фильтра нормализуется.
- Через обёртку публичного `run_pilot` проверяются реальные вызовы локального
  mock API, число пилотов и размер каждого. Проверяются размеры финальных
  аудиторий, совместный контактный лимит и остаток бюджета после пилотов.
- Зависимость решения от результатов пилота проверяет существующий тест
  `test_changed_pilot_results_change_decision_on_identical_public_data`:
  одинаковые публичные данные с противоположными результатами дают разные
  целевые тарифы. Скрытые эффекты симулятора не используются.
- Отсутствие `OPENAI_API_KEY` и ошибки/таймауты, подставленные на границе
  `socket`, не мешают текущему локальному агенту. Реальные подключения в
  новых контрактных тестах запрещены с помощью `unittest.mock.patch`.
- AST исходников проверяется на конкретные вызовы `gc.get_objects`,
  `inspect.getclosurevars`, доступ к closure/frame и приватным членам `env`.
  Поддерживаются простые алиасы. Обычные импорты `inspect`/`gc`,
  `inspect.signature` и `gc.collect` допускаются.

## Ограничения

Сетевые mocks доказывают работоспособность текущего локального пути, но не
корректность отсутствующего LLM fallback. После добавления интеграции нужны
тесты её фактического клиента: ошибка, таймаут и отказ ключа до сетевого вызова.
AST-проверка эвристическая: она не является песочницей и не гарантирует
обнаружение намеренно обфусцированного кода. Оценка runtime относится к
проверенным входам и локальному evaluator. Финальная проверка после слияния
PR выполняется только после подтверждения капитана.
