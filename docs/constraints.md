## Публичный контракт

### Класс `Agent` и `act(env)`

Локальный evaluator делает следующее:

```python
agent_class = importlib.import_module(agent_module).Agent
campaigns = agent_class().act(env)
metrics = env.evaluate(campaigns)  # вызывает evaluator, не агент
```

По умолчанию `agent_module="agent"`; CLI позволяет выбрать модуль через
`--agent`. Требуется доступный класс с именем `Agent`, конструктор без
обязательных аргументов и обычный синхронный метод `act(self, env)`.
Наследование от SDK, декоратор регистрации, `fit`, `train`, сохранённая модель
или отдельный CLI самого агента локальным загрузчиком не требуются.
Существующий `Agent` не объявляет свой `__init__` и аннотации типов метода.

Успешный результат — список словарей кампаний. Исключение из `act`
даёт отчёт `ok=false`; локальный CLI завершается кодом 1 при ошибке хотя бы
одного запуска. Положительный `net_gain` условием `ok=true` не является.

Разрешённый тестами интерфейс агента содержит ровно восемь имён:
`customer_profile`, `tariffs`, `channels`, `remaining_budget`,
`remaining_contacts`, `pilots_left`, `pilot_history`, `run_pilot`.
У Python-класса среды есть `evaluate` и `summary`, но они принадлежат
оболочке проверки и не входят в этот интерфейс. `env.limits` не предоставлен.

### `env.customer_profile`

Свойство возвращает `pandas.DataFrame.copy(deep=True)` с индексом,
сброшенным при создании среды. Минимальные обязательные столбцы:

| Поле | Точный локальный минимум |
| --- | --- |
| `customer_id` | Не пропущен и уникален; валидатор не требует конкретно `int`, хотя CSV содержит целые |
| `current_tariff` | Непустая строка без `;`, значение имеется в `tariffs.tariff_id` |
| `arpu_segment` | Непустая строка без `;` |
| `data_segment` | Непустая строка без `;` |
| `call_segment` | Непустая строка без `;` |
| `predicted_arpu` | Числовые, конечные, неотрицательные значения; проверка конечности приводит массив к `float` |

Таблица не должна быть пустой. Пропуски запрещены во всех обязательных
полях; дополнительные столбцы допускаются и копируются без отдельной
валидации. Валидатор не закрепляет словарь сегментов: допустимые строки
берутся из самой таблицы. Числовые строки не следует считать поддержанным
типом ARPU: после приведения для `isfinite` код сравнивает исходные значения
с нулём. Тип индекса и `customer_id` не являются средством таргетинга.

### `env.tariffs`

Свойство возвращает независимую копию DataFrame. Нужны непустая таблица,
уникальный непустой в смысле отсутствия NA `tariff_id` и конечная числовая
`monthly_fee >= 0`. Проверки на непустую строку для каждого `tariff_id`
отдельно нет; использованные в профиле ID должны удовлетворять строковому
контракту `current_tariff`. Практический формат текущих данных — строковый ID.
Передавать в API следует точное значение ID из таблицы без переименования.

В локальном CSV также есть `data_gb` и `minutes`. Они необязательны,
среда не валидирует их и не использует как фильтры кампаний.
Наличие тарифа в таблице достаточно для выбора `target_tariff`;
списков совместимости, ограничений перехода и скидок публичный API не даёт.

### `env.channels` и состояние ресурсов

`channels` при каждом чтении создаёт новый `dict[str, dict]`:

```python
{
    "push": {"cost": 0.0},
    "sms": {"cost": 4.0},
    "digital_ads": {"cost": 22.0},
    "call": {"cost": 160.0},
}
```

`cost` — условные денежные единицы за контакт. Доступность абонента
в канале, квоты отдельных каналов, частота показов и conversion rate
не предоставлены. Конкретные названия и цены выше — текущая локальная
конфигурация, агент должен читать их из `env`.

`remaining_budget` — `float`, `remaining_contacts` — целый остаток контактов,
`pilots_left` — `Limits.pilots - len(history)`. `pilot_history` — глубокая
копия списка словарей результатов, сначала `[]`. Свойства не имеют setter.
Успешные пилоты сразу меняют остатки; прибыль не пополняет бюджет.

### `env.run_pilot()`

Точная сигнатура из `LocalEnvironment`:

```python
def run_pilot(self, *, target_tariff, channel, n_customers, **filters):
    ...
```

Все три обязательных аргумента именованные. Значения по умолчанию отсутствуют.
`target_tariff` должен присутствовать в словаре тарифов, `channel` — в
`env.channels`. `n_customers` должен быть `numbers.Integral`, но не `bool`:
например, `10` допустимо, `10.0` и `True` — нет. При стандартных лимитах
`10 <= n_customers <= 200`. Поддержанные `filters` перечислены ниже;
`campaign_name`, `customer_ids`, `seed` и произвольные параметры пилота
не разрешены.

Дополнительные условия: среда ещё не финализирована, остался пилот,
аудитория непустая, в ней не меньше `n_customers`, достаточно контактов
и средств на `n_customers * cost`. Размер всей подходящей аудитории
пилота может превышать 5 000: выбирается только запрошенная проба.

Среда выбирает `n_customers` случайных строк без возвращения внутри вызова.
Предыдущие участники не исключаются из следующих выборок и финала.
Успех списывает один пилот, контакты и стоимость, записывает результат
в историю; `act` не должен повторно списывать их в среде.
Обычные нарушения валидации дают `ValueError` до списания. Нарушение
сигнатуры Python, например позиционные аргументы, даёт `TypeError`.

### Структура результата пилота

Возвращается новый словарь с такими ключами:

| Ключ | Тип в локальной среде | Семантика |
| --- | --- | --- |
| `target_tariff` | Тип переданного ID, в demo `str` | Испытанный тариф |
| `channel` | `str` | Испытанный канал |
| Переданные `filter_*` | `str` | Только реально переданные фильтры; отсутствующие не добавляются |
| `pilot_id` | `int` | Номер успешного пилота, начиная с 1 |
| `n_customers` | `int` | Фактический размер пробы |
| `mean_arpu_uplift` | `float` | Среднее абсолютное изменение ARPU на контактированного абонента, до расходов |
| `std_arpu_uplift` | `float` | Выборочное стандартное отклонение индивидуальных изменений, `ddof=1`; не стандартная ошибка |
| `communication_cost` | `float` | `n_customers * channels[channel]["cost"]` |
| `net_gain` | `float` | Сумма исходов именно этой пробы минус её стоимость |

С точностью округления float:
`net_gain = n_customers * mean_arpu_uplift - communication_cost`.
Отрицательное среднее и отрицательный `net_gain` допустимы. Ответ не
содержит индивидуальных ID, исходов, признаков конверсии, контрольной группы
или готового доверительного интервала. Изменение возвращённого словаря
не меняет копию в истории.

### Структура итоговой кампании

```python
{
    "campaign_name": "Example",          # включать по соглашению команды
    "target_tariff": "tariff_11",        # обязательно
    "channel": "push",                   # обязательно
    "filter_arpu_segment": "HIGH",       # необязательно
    "filter_data_segment": "HEAVY;LITE", # необязательно
    "filter_call_segment": "",           # необязательно
    "filter_current_tariff": "",         # необязательно
}
```

Это пример формы, не готовый допустимый план: фактический размер аудитории
и ресурсы нужно проверить. Контейнер кампании — `dict`, общий результат —
`list`, от 1 до 10 кампаний при стандартной конфигурации.
Дополнительные поля запрещены. В частности, финальный словарь не принимает
`n_customers`, `budget`, `customer_ids`, `expected_gain` или `pilot_id`.

`campaign_name` в README представлен как обычное поле, но `_selection`
**допускает его отсутствие**; если поле передано, требуется `str`.
Пустая строка и одинаковые имена нескольких кампаний не запрещены кодом.
Для решения сохраняется более ясное соглашение: передавать содержательное
строковое имя каждой кампании. Обязательность имени у организаторов
пока неизвестна.

Правила фильтрации общие для пилота и финала:

| Поле фильтра | Столбец профиля |
| --- | --- |
| `filter_arpu_segment` | `arpu_segment` |
| `filter_data_segment` | `data_segment` |
| `filter_call_segment` | `call_segment` |
| `filter_current_tariff` | `current_tariff` |

- Отсутствующее поле или `""` не ограничивает соответствующую категорию.
- Иначе требуется строка с точными значениями, разделёнными `;`.
  Внутри одного фильтра действует ИЛИ, между фильтрами — И.
- Сравнение чувствительно к регистру, пробелы не удаляются. Нет wildcard,
  диапазонов, отрицания или числовых условий.
- Все токены должны присутствовать в соответствующем столбце исходного
  профиля. `HIGH;`, `;HIGH`, `HIGH;;LOW`, неизвестные значения и `None`
  недопустимы. Повтор одного корректного токена не размножает строки.
- Пустое пересечение запрещено, даже если каждое значение само по себе
  известно. Отсутствие всех фильтров выбирает всю базу.

Размер финальной кампании равен полному числу строк по фильтрам.
Автоматического обрезания до 5 000, дедупликации разных кампаний или
исключения участников пилота нет. Фильтр текущего тарифа и целевой тариф
независимы: можно предложить исходный тариф, что в локальной модели даёт
нулевой revenue effect, но расходует контакт и стоимость канала.

### CSV экспорта

Порядок `CAMPAIGN_COLUMNS`:

```text
campaign_name,filter_arpu_segment,filter_data_segment,filter_call_segment,filter_current_tariff,target_tariff,channel
```

`make_submission.write_submission` пишет UTF-8, разделитель `,`, заголовок,
концы строк LF, без индекса. Отсутствующие поля становятся пустыми ячейками.
Это производный локальный экспорт; не подтверждено, что организаторы
принимают этот CSV или именно такой набор файлов сдачи.

## Численные must-have локального evaluator

Значения по умолчанию из `Limits`:

| Условие | Точное значение | Где проверяется |
| --- | --- | --- |
| Общие расходы пилотов и финала | `<= 100000.0` | `run_pilot`, `evaluate` |
| Все контакты пилотов и финала, с повторами | `<= 15000` | `run_pilot`, `evaluate` |
| Успешных пилотов до финализации | От 1 до 20 | Непустая история в `evaluate`, верхняя граница в `run_pilot` |
| Размер одного пилота | Целое от 10 до 200 включительно, не `bool` | `run_pilot` |
| Число финальных кампаний | От 1 до 10 включительно | `evaluate` |
| Размер одной финальной кампании | От 1 до 5 000 включительно | Непустая `_selection` и `evaluate` |
| Таймаут локальной оболочки | `0 < timeout <= 600` секунд, по умолчанию 600 | `run_once`, CLI |
| Время `act`, измеренное внутри worker | Не больше 600 секунд | `_worker` |

`Limits` можно переопределить при прямом создании локальной среды; CLI
использует значения по умолчанию. Некоторые тексты ошибок содержат числа
стандартной конфигурации, даже при ином `Limits`: источником проверки служат
поля объекта. Число 23 441 абонент и 21 тариф — параметры генератора,
не обязательный размер входа. 25% бюджета, 2 000 контактов, пробы на 60/80
и внутренний дедлайн 540 секунд — настройки стратегии, не must-have кейса.

`evaluate` сначала валидирует весь план, затем применяет финальные контакты.
Если хотя бы одна кампания отклонена, ни одна финальная кампания ещё не
списана, но ранее выполненные пилоты сохраняются. Успешный `evaluate`
финализирует среду: повторная оценка и новые пилоты запрещены.

## Учёт результата

Для локальной проверки:

```text
baseline_arpu = sum(customer_profile.predicted_arpu)
gross_uplift = sum(лучший фактический эффект каждого затронутого абонента)
communication_cost = стоимость всех пилотных и финальных контактов
net_gain = gross_uplift − communication_cost
total_arpu_after_costs = baseline_arpu + net_gain
```

У нетронутого абонента вклад равен нулю; у затронутого сохраняется лучший
из действительно полученных эффектов, даже если он отрицателен.
Повторный контакт не суммирует эффекты одного абонента, но всегда расходует
контакт и стоимость. `pilot.net_gain` не является изменением общего
`summary.net_gain` при пересечении с предыдущими воздействиями.

Локальный итог также содержит `contacts_used`, `unique_customers`,
`pilots_count`, `remaining_budget`, `remaining_contacts`, а после `evaluate`
добавляются `campaigns_count` и список `campaign_sizes`.
Эти итоговые метрики получает evaluator; они не дополнительный источник
скрытых исходов для агента. Максимизация такой метрики — локальная модель
цели, официальная формула оценки и её временной горизонт неизвестны.

## Требования команды сверх валидации среды

| Требование/различие | Подтверждённый статус |
| --- | --- |
| Пользоваться только восемью членами публичного API | Проверяет `PublicOnlyEnvironment` в тестах агента |
| Не импортировать evaluator и не извлекать скрытые эффекты, не обходить пилоты | Правило решения в README и docstring среды |
| Пилотное основание финального выбора | Тесты проверяют успешный пилот с теми же тарифом и каналом; evaluator требует только хотя бы один пилот вообще |
| Пилот на точно такой же аудитории | Тесты не доказывают это условие; при сужении аудитории возникает перенос оценки, который надо учитывать |
| Непересекающиеся финальные аудитории | Проверяется тестами агента; evaluator допускает пересечения и считает повторные контакты |
| `campaign_name` | Соглашение команды и колонка CSV; валидатор разрешает отсутствие |
| Положительный итог | Цель оптимизации, не условие допустимости; отрицательные результаты сохраняются |
| Внешний LLM | Не добавлять в рамках текущего запроса; ограничения организаторов на внешние сервисы ещё не получены |

Ограничения публичного API не следует обходить через `_rates`, `_noise`,
`_best`, `_profile`, `_limits`, seed evaluator, reflection или прямой импорт
симулятора. Изучение кода среды здесь нужно для контракта и учёта;
числа скрытой модели не являются входными признаками решения.

## Что необходимо уточнить по официальному пакету

1. Точный загрузчик `Agent`, Python/зависимости, формат и состав сдачи.
2. Реальные схемы `customer_profile`, истории тарифов, traffic,
   `arpu_monthly`, словари признаков и тарифов, ключи и даты отсечения.
3. Сигнатуру `run_pilot`, названия и единицы результата, правила выборки,
   пересечений, списания при ошибках и доступность состояния ресурсов.
4. Обязательные поля кампании, синтаксис фильтров и способ задать аудиторию;
   необходимость пилота для каждой комбинации или только для плана.
5. Подтверждение бюджетов, контактов, количества/размеров пилотов и кампаний,
   времени/памяти, доступности сети и внешних сервисов.
6. Целевую метрику, горизонт ARPU, стоимость, обработку повторных контактов
   и отрицательных эффектов, правила использования исторических данных.
7. Манифест неизменяемых организаторских файлов и официальные команды проверки.

До получения этих материалов совместимость можно утверждать только
для локальной среды. Команды и фактически выполненные проверки, включая
наблюдавшееся несовпадение текста ошибки в одном тесте, зафиксированы
в [architecture.md](architecture.md#команды-проверки).
