# Безопасность репозитория

Текущий `Agent` работает локально: внешние API, LLM и секреты ему не нужны.
Среда и evaluator в этом репозитории созданы командой. Они не являются
официальным пакетом организаторов или защищённой песочницей.

## Переменные окружения

`.env.example` содержит только пустую переменную `OPENAI_API_KEY` для возможной
согласованной интеграции. Текущий агент её не использует и автоматически `.env`
не загружает. Если интеграция появится, передавайте ключ через окружение процесса
или хранилище secrets CI, а не через исходный код, аргументы командной строки,
README, логи или CSV. Значения окружения нельзя выводить в диагностику.

Вызовы внешнего API должны иметь timeout, обработку исключений и полностью
рабочую локальную fallback-логику. Отсутствие ключа не должно ломать основной
сценарий. Такие свойства нужно проверять отдельно при добавлении интеграции.

## Что нельзя коммитить

- `.env` и локальные варианты с реальными значениями; пустой `.env.example`
  разрешён.
- API-ключи, токены, пароли, приватные ключи, файлы credentials и служебные
  данные, которые организаторы не разрешили публиковать.
- Виртуальные окружения, локальные настройки IDE, логи и временные результаты
  тестов. Перед публикацией проверяйте содержимое Git diff и список файлов.
- Персональные данные и конфиденциальные выгрузки. Синтетический статус
  предоставленных данных нужно подтверждать по их источнику.

`.gitignore` предотвращает случайное добавление новых файлов, но не удаляет
секрет из уже отслеживаемого файла или истории Git. Не используйте `git add -f`
для обхода правил. Сгенерированный `submission.csv` является артефактом кейса
и намеренно не исключён из Git.

## Разрешённые проверки

Разрешены статический анализ текущего репозитория и его зависимостей, поиск
секретов, локальные unit/integration tests и локальный запуск приложения с
разрешёнными данными. Агент может использовать только публичный API среды и
результаты `env.run_pilot()`. Нельзя получать скрытые эффекты через `__closure__`,
`gc.get_objects`, `inspect.getclosurevars`, секретные файлы организатора или
аналогичные обходы.

Запускайте из корня репозитория с Python проекта:

```powershell
python scripts/preflight.py
python -m unittest discover -s tests -v
python local_eval.py
```

Preflight использует только стандартную библиотеку Python и локальный Git.
Он не импортирует агент и не требует NumPy/pandas. Он проверяет существование
`agent.py`, синтаксическое наличие `Agent.act`, README, задокументированную
команду `python local_eval.py`, отсутствие `.env` среди файлов, попадающих в Git,
и очевидные секреты в отслеживаемых и неигнорируемых новых текстовых файлах.
Игнорируемый локальный `.env` не читается. Если `submission.csv` уже отслеживается
или существует, проверяется его наличие и непустое содержимое; если он ещё не
генерировался, выводится `SKIP`, а не ложная ошибка.

Сообщения содержат только путь и тип проверки, без найденного значения и
исходной строки. Код возврата `0` означает, что выбранные проверки прошли;
`1` — найдена проблема или проверку не удалось выполнить. Сигнатурный поиск
может пропустить секрет или дать ложное срабатывание. Бинарные и игнорируемые
файлы, история Git и внешние библиотеки этой командой не проверяются. Для
поиска используются текстовые файлы UTF-8; пропущенные бинарные или неизвестные
кодировки отмечаются `SKIP` и требуют отдельного разбора.
Статическое наличие `Agent.act` не доказывает его исполнимость: для этого
нужны unit tests и evaluator. Успешный preflight не подтверждает совместимость
с отсутствующим официальным пакетом.

## Запрещённые сетевые действия

Запрещены сканирование сети хакатона и устройств других участников, атаки на
Wi-Fi, перехват трафика, brute force, DoS и нагрузочные атаки. Проверка внешних
адресов на безопасность допускается только при письменном разрешении.
Работа с GitHub для согласованной разработки не даёт разрешения сканировать
его или другую инфраструктуру.

## Сообщение об инциденте

При обнаружении утечки прекратите дальнейшую публикацию и сообщите капитану
команды и организаторам через установленный ими закрытый канал. Передавайте
только тип проблемы, путь, номер коммита и описание последствий; не копируйте
полный секрет в issue, PR, чат или отчёт. Владелец секрета должен отозвать или
заменить его. Очистку истории согласуйте с капитаном; удаления из текущего
файла недостаточно. Не эксплуатируйте обнаруженную уязвимость и не проверяйте
доступ к чужим ресурсам.
