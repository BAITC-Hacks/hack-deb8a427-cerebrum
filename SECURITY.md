# Безопасность репозитория

Агент использует локальные данные официального пакета участника и публичный
API среды. `environment.py`, `mock_environment.py`, `scoring_core.py`,
`agent_template.py`, `local_eval.py` и `make_submission.py` получены из
пакета организаторов и сохраняются без изменений. Это учебный синтетический
кейс, а не защищённая песочница. Происхождение файлов и контрольные суммы
описаны в `scripts/participant_package_manifest.json`; проверка хеша
подтверждает совпадение байтов с локальным источником, но сама по себе не
предоставляет права на публикацию.

## Секреты и локальные данные

Базовый режим `Agent` работает без ключа и сетевого сервиса. Опциональный
режим `python run.py --llm` использует `OPENAI_API_KEY` из окружения процесса;
`.env` автоматически не загружается. Модель получает только агрегаты до
20 сегментов, без строк и идентификаторов абонентов. Адрес API фиксирован:
`https://api.openai.com/v1/responses`, параметр `store=false`.
Не записывайте секреты в код, аргументы командной строки, логи, README или CSV.

LLM делает максимум один запрос на запуск. Ожидание ограничено 8 секундами;
отказ, неверный JSON, неизвестные или повторные номера гипотез дают локальную
запасную логику. Ответ не исполняется как код и не заменяет пилотные наблюдения.
Превышение времени завершает ожидание; фоновый сетевой поток имеет собственный
таймаут и не блокирует завершение процесса. Ошибки провайдера не выводятся.
Внешний процесс проверки ограничен 600 секундами. Сам агент проверяет дедлайн
540 секунд между пилотами; он не может прервать зависший `env.run_pilot()`.

Панель привязана к `127.0.0.1`, проверяет Origin запросов запуска и принимает
только числовой seed. Запросы сериализованы; данные браузера вставляются как
текст. ZIP-импорт переносит только файлы манифеста после полной проверки хешей.

Входные CSV пакета и `data/` остаются локально и исключены из Git.
`submission.csv` — обязательный артефакт сдачи: после проверки его нужно
добавить в Git и просмотреть содержимое на предмет случайных секретов.
Пакет храните вне репозитория; для восстановления
используйте `python run.py --package <ZIP-или-каталог>`.
Организаторы называют данные синтетическими. Не публикуйте их отдельно без
разрешения. `.gitignore` не удаляет уже отслеживаемые файлы и не очищает
историю: перед отправкой проверяйте `git status`, `git diff --cached --name-only`
и содержимое изменений. Не используйте `git add -f` для обхода исключений.

## Допустимые проверки

Из корня репозитория после импорта пакета:

```powershell
python scripts/preflight.py
python -m unittest discover -s tests -v
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

`preflight.py` — локальная статическая проверка на стандартной библиотеке
Python и Git. Она ищет очевидные секреты в отслеживаемых и неигнорируемых новых
текстовых файлах, проверяет точку входа, README и наличие экспорта, если он уже
создан. Игнорируемые входные CSV, бинарные файлы, история Git, зависимости и скрытые
эффекты не входят в её охват. Сообщения выводят путь и тип проблемы, без
совпавшего значения; путь сам по себе не должен содержать секрет. Возможны
пропуски и ложные срабатывания. Успешный preflight не заменяет запуск
официального evaluator, его текстового отчёта и просмотр Git diff.

Агенту разрешены публичные свойства `env`, предоставленные участникам
исторические CSV, `env.run_pilot()` и результаты пилотов. Запрещено извлекать
скрытые эффекты через `__closure__`, `gc`,
`inspect`, приватные поля среды, файлы оценки или аналогичные обходы.
Исторические CSV относятся к другой выборке и не раскрывают эффекты целевой
аудитории. Не изменяйте официальные скрипты проверки и подсчёта результата.

## Сеть и инциденты

Не сканируйте сеть хакатона, устройства участников и внешние адреса без
письменного разрешения; запрещены перехват трафика, подбор паролей и
нагрузочные атаки. Работа с GitHub для разработки не даёт разрешения
проверять чужую инфраструктуру.

При обнаружении утечки остановите публикацию и сообщите капитану команды и
организаторам через закрытый канал: тип проблемы, путь, коммит и последствия.
Не копируйте полный секрет в issue, PR, чат или отчёт. Владелец должен отозвать
или заменить секрет; удаление строки из текущего файла не очищает историю Git.
