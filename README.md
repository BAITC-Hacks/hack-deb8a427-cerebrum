# Cerebrum — агент тарифных маркетинговых кампаний

Cerebrum выбирает аудитории, тарифы и каналы связи для кампаний Beeline. Метод
`Agent.act(env)` использует публичные данные среды, проводит пилоты через
`env.run_pilot()` и возвращает план кампаний. Это решение команды для
[официального пакета участника](PARTICIPANT_GUIDE.md), полученного от
организаторов. Данные пакета синтетические; результаты не описывают реальный
бизнес оператора и не предсказывают судейский балл.

## Подготовка

Нужны Python 3.11+, Git и зависимости из `requirements.txt`. Команды ниже
выполняются из корня репозитория. На Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Если используется активированное окружение, далее можно писать `python` вместо
`.\.venv\Scripts\python.exe`. На Linux и macOS путь к Python окружения другой.
LLM, GPU и API-ключ для текущего агента не требуются.

Сохраните каталог пакета участника вне репозитория и импортируйте его локально:

```powershell
$participantPackage = 'C:\path\to\beeline_case_participants'
.\.venv\Scripts\python.exe scripts/import_participant_package.py --source $participantPackage
```

Скрипт сверяет файлы с `scripts/participant_package_manifest.json` и
восстанавливает входные CSV в корне и `data/`. Входные CSV локальны и
исключены из Git. Сгенерированный `submission.csv` — обязательный
артефакт сдачи; после проверки его нужно добавить в Git. Файлы среды и evaluator из пакета
(`environment.py`, `mock_environment.py`, `scoring_core.py`, `agent_template.py`,
`local_eval.py`, `make_submission.py`) сохраняются без изменений. Исходный
`PARTICIPANT_GUIDE.md` хранится отдельно от кода команды. Подробности
происхождения — в [THIRD_PARTY.md](THIRD_PARTY.md).

## Проверка и экспорт

После импорта данных запускайте команды официального пакета:

```powershell
.\.venv\Scripts\python.exe local_eval.py
.\.venv\Scripts\python.exe local_eval.py --runs 10
.\.venv\Scripts\python.exe make_submission.py
```

Если виртуальное окружение активировано, те же команды короче:

```powershell
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

`local_eval.py` проверяет работу агента на мок-эффектах. Одиночный запуск
использует seed 42; `--runs 10` — seed 0–9. В выводе нужно проверить, что
агент провёл пилоты, кампании не отброшены и лимиты соблюдены. Официальный
скрипт перехватывает исключения и может завершиться с кодом 0 при `FAIL`,
поэтому один код возврата не означает зачёт. Экспортёр создаёт
`submission.csv`; перед сдачей проверьте наличие и содержимое файла:

```powershell
Test-Path submission.csv
Get-Content submission.csv -TotalCount 5
git status --short -- submission.csv
```

Для проверки кода команды:

```powershell
.\.venv\Scripts\python.exe scripts/preflight.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
git diff --check
```

В `docs/test-report.md` хранятся результаты прежних проверок синтетической
среды команды. Результаты официального evaluator следует записывать отдельно
после фактического запуска на текущем коммите. Опции старого evaluator
`--json`, `--scenario` и `--data-dir` к официальным командам не относятся.

## Контракт и подход

По [заданию участника](PARTICIPANT_GUIDE.md) агент возвращает от 1 до 10
кампаний. Для каждой нужны `target_tariff` и `channel`; фильтры по публичным
категориям аудитории необязательны. Допустимы не более 5 000 абонентов на
кампанию, 15 000 контактов и 100 000 у.е. расходов суммарно. Можно провести
не более 20 пилотов по 10–200 абонентов. Пилоты расходуют те же контакты и
бюджет, что финальные кампании. Агент должен учитывать результаты пилотов:
эффекты судейства отличаются от мок-эффектов.

`agent.py` содержит точку входа и управление пилотами, `candidates.py` —
подготовку вариантов аудиторий и тарифов. Агент читает только публичный API
`env`, открытые исторические CSV пакета и результаты `run_pilot()`.
Он не обращается к скрытым эффектам, внутренностям среды или файлам оценки.
Исторические CSV относятся к другой выборке абонентов; они помогают строить
гипотезы, но не раскрывают отклик целевой аудитории.

Подробности: [архитектура](docs/architecture.md),
[контракт и лимиты](docs/constraints.md), [план проверок](docs/test-plan.md),
[чек-лист сдачи](docs/final-checklist.md).

## Границы результата и безопасность

Официальный `local_eval.py` использует код подсчёта результата из пакета, но
мок-эффекты. Успех локальных прогонов не гарантирует результат на других
эффектах судейства. Формула учитывает процентный эффект от ARPU уникального
абонента и стоимость каждого контакта. Ошибки и ограничения проверяются
официальными скриптами, а не прежней синтетической средой команды.

CSV пакета синтетические по утверждению организаторов, но их не следует
публиковать без отдельного разрешения. Не коммитьте входные CSV, ключи и
`.env`; проверенный `submission.csv` включите в сдачу. Правила и
ограничения статической проверки — в
[SECURITY.md](SECURITY.md). Зависимости и происхождение кода пакета — в
[THIRD_PARTY.md](THIRD_PARTY.md). Отдельной лицензии собственного кода команды
в репозитории пока нет.
