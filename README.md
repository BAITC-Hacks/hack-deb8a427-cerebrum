# Cerebrum — агент тарифных маркетинговых кампаний

Фундамент решения для HackAlem AI: `agent.py` с классом `Agent` и методом
`act(env)`, локальная среда, проверки и экспорт демонстрационных кампаний.

Текущее продолжение: [результаты этапов 2–4](docs/stages.md) и
[синтетический набор по предоставленному ТЗ](docs/synthetic_data.md).
Создать полный набор: `python generate_case_data.py`; проверить его:
`python local_eval.py --data-dir synthetic_case`. Генератор не перезаписывает
существующий каталог. Численные результаты ниже, датированные разведкой,
относятся к прежнему baseline; актуальное сравнение находится в журнале этапов.

**Среда, генератор данных и evaluator в этом репозитории созданы командой и
не являются официальным пакетом организаторов.** Они реализуют локальный
контракт на основе предоставленного описания кейса. Совместимость с официальным
`env`, форматом сдачи и судейский балл пока не подтверждены. Синтетические данные
и эффекты не воспроизводят настоящую базу абонентов или скрытые эффекты.

## Запуск

Нужен Python 3.11 или новее; зависимости зафиксированы в `requirements.txt`:
NumPy 2.3.5 и pandas 3.0.1. Команды выполняются из корня репозитория.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python local_eval.py
python local_eval.py --runs 10
python local_eval.py --runs 10 --scenario adverse
python local_eval.py --runs 10 --scenario channel_shift
python -m unittest discover -s tests -v
python make_submission.py
git diff --check
```

`local_eval.py` по умолчанию создаёт данные в памяти. Каждый запуск использует
новую среду; `--runs 10` проверяет десять последовательных seed, начиная с
`--seed` (по умолчанию 42). `--json` выводит отчёт с кампаниями, историей пилотов
и метриками. Код возврата — 0 при успехе всех запусков, 1 при ошибке.
Положительная прибыль не является условием успешной проверки лимитов.

`make_submission.py` сначала запускает локальную проверку, затем пишет
`submission.csv`. Это демонстрационный экспорт, не подтверждённая официальная
заявка. Повторный запуск перезаписывает указанный выходной CSV.

При необходимости можно отдельно записать синтетические CSV:

```powershell
python generate_demo_data.py
python local_eval.py --data-dir demo_data
python make_submission.py --data-dir demo_data --output demo_submission.csv
```

Генератор создаёт 23 441 синтетического абонента и 21 синтетический тариф.
Файлы `demo_data/customer_profile.csv` и `demo_data/tariff_dictionary.csv`
воспроизводимы при одинаковом seed. Генератор отказывается перезаписывать
существующие CSV: для повторной генерации укажите новый `--output`.
Каталог `demo_data` исключён из Git.

## Локальный публичный контракт `env`

Этот контракт описывает текущий код команды; его нужно сверить с официальным
пакетом при получении.

| Член | Тип и содержимое |
| --- | --- |
| `customer_profile` | Копия pandas DataFrame: `customer_id`, `current_tariff`, `arpu_segment`, `data_segment`, `call_segment`, `predicted_arpu` |
| `tariffs` | Копия pandas DataFrame: обязательные `tariff_id`, `monthly_fee`; генератор также добавляет `data_gb`, `minutes` |
| `channels` | Словарь `{channel: {"cost": cost_per_contact}}` |
| `remaining_budget` | Остаток бюджета после пилотов |
| `remaining_contacts` | Остаток контактов после пилотов |
| `pilots_left` | Остаток количества пилотов |
| `pilot_history` | Копия списка результатов проведённых пилотов |
| `run_pilot(...)` | Проведение пилота и списание его ресурсов |

Локальные каналы: `push` — 0, `sms` — 4, `digital_ads` — 22,
`call` — 160 условных единиц за контакт. Агент читает доступные каналы,
стоимость и тарифы из `env`, а не задаёт эти значения самостоятельно.

```python
result = env.run_pilot(
    target_tariff=tariff_id,
    channel=channel_name,
    n_customers=60,
    filter_arpu_segment="HIGH",
    filter_data_segment="HEAVY",
)
```

Результат содержит `pilot_id`, `n_customers`, `mean_arpu_uplift`,
`std_arpu_uplift`, `communication_cost`, `net_gain`, тариф, канал и переданные
фильтры. Среднее и стандартное отклонение — **абсолютное изменение ARPU на
абонента**, не процент; стандартное отклонение выборочное (`ddof=1`).

`Agent.act(env)` возвращает список словарей кампаний. Поля:
`campaign_name`, `target_tariff`, `channel` и необязательные фильтры
`filter_arpu_segment`, `filter_data_segment`, `filter_call_segment`,
`filter_current_tariff`. Фильтры соответствуют одноимённым столбцам профиля
без префикса `filter_`. Значения внутри фильтра разделяются `;` и объединяются
через ИЛИ; разные фильтры — через И. Пустой или отсутствующий фильтр означает
всю соответствующую категорию. Неизвестные значения и поля отвергаются.
Размер финальной кампании определяется фильтрами; поля для произвольного
обрезания аудитории нет.

## Лимиты и локальный результат

| Ограничение | Значение |
| --- | --- |
| Финальные кампании | От 1 до 10 |
| Абоненты на финальную кампанию | Не более 5 000 |
| Все контакты, включая пилоты | Не более 15 000 |
| Все расходы, включая пилоты | Не более 100 000 |
| Успешные пилоты | От 1 до 20 |
| Абоненты в каждом пилоте | От 10 до 200 |
| Локальное выполнение | Таймаут дочернего процесса до 600 секунд |

Каждый повторный контакт расходует контактный лимит и бюджет. До применения
финальных кампаний среда проверяет весь план. В локальном расчёте на каждого
уникального затронутого абонента учитывается лучший эффект среди его пилотных
и финальных контактов. Первый отрицательный эффект сохраняется отрицательным;
нулевой эффект необработанного абонента его не заменяет.

`net_gain = сумма этих эффектов − стоимость всех контактов`.
`total_arpu_after_costs = сумма predicted_arpu по базе + net_gain`.
Это метрики локальной модели, а не прогноз судейского балла.

Сценарий `mixed` создаёт случайные смешанные эффекты, `adverse` — неблагоприятные,
`channel_shift` — перестановку откликов между каналами. Изменение seed меняет
синтетические эффекты. Эти сценарии проверяют устойчивость исполнения и учёт
плохих исходов; они не доказывают качество на неизвестных данных.

Проверенные локальные результаты 23 сентября 2026 года:

| Команда | Результат |
| --- | --- |
| `python local_eval.py` | seed 42: 3 кампании, 20 пилотов, 10 775 контактов, расходы 97 842, `net_gain=2708120.55`, время `act` 0,296 с |
| `python local_eval.py --runs 10` | seed 42–51: 10/10 допустимых планов, положительный `net_gain` в 10/10 |
| `python local_eval.py --runs 10 --scenario channel_shift` | 10/10 допустимых планов |
| `python local_eval.py --scenario adverse` | seed 42: 1 кампания, 20 пилотов, 1 264 контакта, расходы 2 040, `net_gain=-273171.77` |
| `python generate_demo_data.py` и `python local_eval.py --data-dir demo_data` | CSV созданы; основной результат совпал с данными в памяти |
| `python make_submission.py` (дважды) | Совпадающий SHA-256 выходного CSV |
| `python -m unittest discover -s tests -v` | 18 тестов пройдены за 2,628 с |
| `python local_eval.py --agent agent_template` | 2 пилота, 1 допустимая кампания |

Время зависит от машины. Отрицательный результат `adverse` ожидаем: проверка
сохраняет убытки и подтверждает допустимость плана, а не прибыльность.

## Как агент принимает решения

Агент строит непересекающиеся аудитории по публичным сегментам, при необходимости
делит их по текущим тарифам и звонкам. Для каждой группы рассматривает до трёх
тарифов по цене и доступной публичной истории другой выборки. Сначала проводит
пробы до 30 контактов на дешёвом канале, затем уточняет перспективные или
неопределённые варианты пробами 80–200 и проверяет другие каналы.
Явно убыточные варианты не подтверждаются. Достигать 20 пилотов не обязательно.

На пилоты выделяется до 25% начального бюджета и до 2 000 контактов; отдельно
резервируются ресурсы хотя бы для одной представимой финальной аудитории.
Остатки ресурсов проверяются перед каждым пилотом. Финальные комбинации тарифа,
канала и исходной аудитории должны иметь успешный пилот. При нехватке ресурсов
финальная аудитория сужается реальными категориальными фильтрами.

Кампании ранжируются по оценке `(средний эффект − 2 × стандартная ошибка − цена
контакта) × размер аудитории`. Если положительных кандидатов нет, агент выбирает
малую проверенную аудиторию с наилучшей оценкой, поскольку требуется минимум
одна кампания. Убыток при этом возможен. Стандартная ошибка здесь — эвристика,
не доказанная доверительная гарантия после адаптивного выбора и сужения аудитории.

`agent.py` не импортирует симулятор, не обращается к приватному состоянию среды,
не использует `closure`, `gc`, `inspect`, сетевые запросы или LLM.
API-ключи для работы не нужны. Если внешние сервисы будут добавлены позднее,
секреты должны поступать только через переменные окружения, а вызовы — иметь
таймаут, обработку ошибок и полноценный локальный fallback.

Отсутствующие признаки отключают соответствующий фильтр, а не создают новую
категорию; все строки аудитории сохраняются. Ошибка или некорректный ответ
пилота не разрешает финальную кампанию и не возвращает уже потраченные ресурсы.
Число попыток ограничено 20, включая неудачные. При полном отказе пилотов,
неизвестных ID тарифов или невозможной аудитории валидный план не гарантируется.

## Что ещё требуется для официальной сдачи

- Получить официальный пакет и сверить поля, типы, фильтры, результат пилота,
  ограничения, зависимости и формат сдачи. При расхождении адаптировать агент;
  локальные fixtures заменить или отделить после проверки происхождения файлов.
- Запустить проверки организаторов на официальных данных. Предоставленные ими
  evaluator, датасеты и скрипты проверки изменять не требуется.
- Проверить качество на независимых эффектах. Сейчас ограниченное исследование
  может пропустить лучший тариф или дорогой канал; сужение аудитории переносит
  оценку из более широкого пилота и может вносить смещение.
- Проверить представимость аудиторий: если доступные фильтры не позволяют
  выделить допустимую группу либо нет ресурсов для успешного пилота и кампании,
  агент сообщает об ошибке вместо возврата непроверенного плана.
- Сверить ограничение времени в официальной среде. Агент проверяет внутренний
  дедлайн 540 секунд между пилотами, но это не прерывает зависший вызов чужого
  `env`. Локальный evaluator завершает дочерний процесс по таймауту до 600 секунд;
  запуск/очистка процесса могут добавить небольшое время оболочки.

Локальная среда является тестовым инструментом, а не защищённой песочницей.
Работа с закрытыми данными организаторов и обход пилотов не входят в решение.
